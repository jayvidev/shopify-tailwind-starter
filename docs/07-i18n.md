# 07 — Copy and translations

Four files, two audiences.

| File | Audience | Used by |
|---|---|---|
| `locales/es.json` | Shoppers | `{{ 'key' | t }}` in Liquid |
| `locales/en.default.json` | Shoppers | fallback locale |
| `locales/es.schema.json` | Merchant | `"t:…"` in `{% schema %}` |
| `locales/en.default.schema.json` | Merchant | fallback locale |

`en.default.*` is what Shopify falls back to when there's no file for the active
language. It must stay in **English** — that's the point of a fallback.

## Storefront copy

```liquid
{{ 'accessibility.skip_to_text' | t }}
```

Filters aren't allowed in `render` arguments, so assign first:

```liquid
{%- assign label = 'accessibility.skip_to_text' | t -%}
{% render 'form-button', text: label %}
```

## Copy that JavaScript renders

Strings the JS produces on its own can't use `| t`. They go through
`window.theme.strings`, set once in `layout/theme.liquid`, and are read with
`t()` from `src/strings.ts`:

```ts
import { t } from '@/strings'

this.discountError = t('discountInvalid')
```

To add one:

1. Add the key to `javascript` in **both** `es.json` and `en.default.json`.
2. Add it to `DEFAULTS` in `src/strings.ts` — that's also the type, so the key
   is checked at compile time.
3. Render it into `window.theme.strings` in `layout/theme.liquid`.

The defaults in `strings.ts` are a safety net, not the source of truth. If
Liquid doesn't inject a key you'll get readable text instead of `undefined`.

## Schema labels

Every `name`, `label`, `info`, `content` and `placeholder` in a `{% schema %}` is
a `t:` key:

```json
"label": "t:sections.hexacore_grid.settings.padding_top.label"
```

Key shape mirrors the schema:

```
sections.<file_handle>.name
sections.<file_handle>.settings.<setting_id>.label
sections.<file_handle>.settings.<setting_id>.info
sections.<file_handle>.settings.<setting_id>.options.options__<n>.label
sections.<file_handle>.blocks.<block_type>.name
sections.<file_handle>.blocks.<block_type>.settings.<id>.label
sections.<file_handle>.presets.name
```

`<file_handle>` is the file name with dashes turned into underscores:
`hexacore-grid.liquid` → `hexacore_grid`.

Settings without an `id` — `header` and `paragraph` — get a positional key
(`header__1`, `header__2`), numbered per type in schema order. **Inserting a
header shifts the ones after it**, so re-check the keys when you do.

## Rules

- **Section `name` is capped at 25 characters.** Only the default locale is
  validated, so an over-long English name fails while the Spanish one passes.
- **Escape HTML in translations.** A description containing a literal
  `<iframe>` is parsed as markup and reported as unclosed. Write `&lt;iframe&gt;`.
- **Never touch setting `id`s or block `type`s.** Those are the keys the
  merchant's saved content is stored under — renaming one loses their content.
  Translating labels is safe precisely because it doesn't touch them.
- Run `pnpm shopify theme check` after editing schemas or locales.
