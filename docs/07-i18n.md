# 07 — Copy and translations

Two files, one audience: shoppers.

| File | Used by |
|---|---|
| `locales/en.default.json` | `{{ 'key' | t }}` — and the fallback locale |
| `locales/es.json` | the same keys in Spanish |

`en.default.json` is what Shopify falls back to when there's no file for the
active language, so it must stay in **English** — that's the point of a fallback.
A shop whose primary language is Spanish still keeps the English default file.

There are **no `*.schema.json` files**: schema labels are written inline in
English. See "Schema labels" below.

## Storefront copy

```liquid
{{ 'accessibility.skip_to_text' | t }}
```

Filters aren't allowed in `render` arguments, so assign first:

```liquid
{%- assign label = 'accessibility.skip_to_text' | t -%}
{% render 'button', label: label %}
```

## Copy that JavaScript renders

Strings the JS produces on its own can't use `| t`. They go through
`window.theme.strings`, set once in `layout/theme.liquid`, and are read with
`t()` from `src/strings.ts`:

```ts
import { t } from '@/strings'

this.discountError = t('discountInvalid')
```

To add one:

1. Add the key to `javascript` in **both** `es.json` and `en.default.json`.
2. Add it to `DEFAULTS` in `src/strings.ts` — that's also the type, so the key
   is checked at compile time.
3. Render it into `window.theme.strings` in `layout/theme.liquid`.

The defaults in `strings.ts` are a safety net, not the source of truth. If
Liquid doesn't inject a key you'll get readable text instead of `undefined`.

## Schema labels

Schema strings — `name`, `label`, `info`, `content`, option labels — are written
inline, in English:

```json
{ "type": "checkbox", "id": "show_vendor", "default": false, "label": "Show vendor" }
```

The alternative is `t:` keys plus a pair of `*.schema.json` files. This starter
skips it: those labels are read only by whoever edits the theme, and a second
translation layer for them drifts out of sync for no gain. If a shop needs
translated editor labels, add the `t:` keys and the schema locale files in that
theme, and document the change there.

Storefront copy is different, and always goes through `locales/`. If a shopper
can read it, it's a translation key.

## Rules

- **Section `name` is capped at 25 characters.**
- **Escape HTML in translations.** A description containing a literal
  `<iframe>` is parsed as markup and reported as unclosed. Write `&lt;iframe&gt;`.
- **Never touch setting `id`s or block `type`s.** Those are the keys the
  merchant's saved content is stored under — renaming one loses their content.
  Translating labels is safe precisely because it doesn't touch them.
- Run `pnpm shopify theme check` after editing schemas or locales.
